Schedule

What each setting does

Enable the day/night schedule
Off by default. While it is off, nothing here has any effect and encodes run exactly as they always have. All times on this page are this PC's local clock, so daylight saving changes are followed automatically.
Daytime window
The hours you want the PC kept responsive for whoever is using it. Everything outside the window is "off-hours". Same every day uses one window for all seven days. Weekdays and weekends uses one window for Monday to Friday and another for Saturday and Sunday. Each day of the week gives every day its own window.
Start and end times
24-hour local time. The window may cross midnight (for example 22:00 to 06:00); it belongs to the day it starts on. Tick Run Off-hours Priority All Day on a window to give that day no daytime window at all: it runs at the off-hours priority for the whole day and is never held.
Daytime priority
How strongly the encoder competes with everything else on this PC during the daytime window. Lower levels leave more of the CPU for other programs; the encode simply takes longer.
Off-hours priority
The priority outside the daytime window. Normal is how encodes ran before this feature existed. An encode that is already running when the window changes switches priority immediately, without restarting.
Priority levels and CPU use
HandBrake spreads an encode across every CPU core whatever the priority, so an encode will try to use nearly all of the CPU. Priority doesn't change how much CPU an encode wants - it decides who wins when other programs want CPU time too.
  • Low - the encode only gets CPU time nothing else wants. Other programs run as if it weren't there, but the encode can crawl, or nearly stall, while the PC is busy.
  • Below Normal - the encode yields to ordinary programs. Everyday use stays smooth and the encode takes whatever is left; the usual choice for the daytime.
  • Normal - the encode and other programs share the CPU equally. CPU use sits near 100% and a busy PC can feel slower. This is how encodes ran before this feature existed.
  • Above Normal - the encode wins most contests with ordinary programs. Encodes finish sooner, but other programs may stutter while it runs.
  • High - the encode is strongly favored over ordinary programs. Expect a noticeably sluggish PC while it runs; best when nobody is using the computer.
  • Realtime - the encode outranks nearly everything, including parts of Windows itself, and can make the PC freeze or become unresponsive. Needs administrator rights; without them Windows treats it as High.
Only encode during off-hours
Holds the queue during the daytime window: no new file starts until off-hours begin. Files are still found and queued in arrival order while they wait, and the queue's order is untouched. The queue completion estimate on the Monitor page includes the time spent waiting.
If the daytime starts mid-encode
Only used with Only encode during off-hours. Finish the current file, then hold never interrupts a running encode; it carries on and the queue holds afterwards. Suspend it until off-hours freezes the running encode when the window starts and continues it when off-hours return (it keeps its temporary file and memory in the meantime).
Run anyway
Shown here and on the Monitor page while the queue is held. It releases the hold for the rest of the current daytime window and starts encoding right away; the hold returns at the next window change. It is never saved. Stop Monitoring and pressing Resume on a suspended encode also release the hold.
